# モーネ：譜面の棒を波打たせる実装案

2026-11-20実装済み。HP75％で棒を曲げ、HP50％で波が乱れてから形をそろえます。各会話後に2周波打つ演出を接続しています。
実装は `js/plugins/KNH_ZXC_Battle_Mone.js`、呼び出しはトループ46のHP75％・50％ページにあります。
追加の台詞や魔法絵は作成していません。モーネの戦闘用仮絵は別途、セル内で1/2へ縮小しています。

## 最初に試す演出

HP75％の「じゃあ　これは／どうかな？」の直後に棒が柔らかく曲がります。
曲がり始める演出を待ってから、みぃーの「なんだ！？」、モーネの「ほら、もっと／遊ぼうよ！」が続きます。
会話中は曲がった状態を保持し、次の演奏可能な譜面の頭から位相と2周分の時間を進めます。
グヌロッベンの破壊と違い、切れ目を作らず、モーネが遊ぶように一本の棒を曲げます。
既存アニメーション6「キラーン」を45％の大きさで添え、既存SE `00_kiran` を使います。
棒は2周の間うねり、最後の1拍でまっすぐに戻す構成をまず試します。
HP50％では、下記の「波をそろえる」演出を実装しています。HP25％には追加の発動を設定していません。

## HP50％：波をそろえる

会話の正文は `tools/castle_upper_maps/mone_dialogue.cjs` の `during[1]` です。
「さあ！もっと／ヒートアップだよ／ついてこれるかい？」の後、1拍かけて波を不揃いにします。
「あ、ちょっと／待って」「波が汚い」の間は不揃いな形を保持します。
その後2拍かけて形をそろえ、「…うん／綺麗になった／続けようか」、みぃーの「…」が続きます。
みぃーがいない場合は、その返答だけ省略します。話者を主人公へ代替しません。

`disorderMoneWave(24, 2)` と `alignMoneWave()` の直後に、それぞれ `moneWaveArrange` のウェイトを置いています。
波の乱れは、元のSin波に2つの固定した細かい波を加え、混合量を0→1→0に補間して作ります。
毎フレームの乱数やノイズの点滅は使いません。棒・音符・カーソル・長押し帯は同じ変形を使います。
形がそろうと混合量は厳密に0になり、元の滑らかなSin波へ戻ります。

75％の波が残っていれば、その時点の形・振幅を引き継ぎます。すでに終わっていれば、新しい波を滑らかに立ち上げます。
会話中に形を変える時間は効果の2周に含めず、戦闘再開後から数えます。撃破・中断時は従来どおり解除します。

## 曲線とタイミング

棒の横位置を `u = x / width` とし、縦の変位を一か所で計算します。

```js
offsetY = amplitude * Math.pow(Math.sin(Math.PI * u), 2)
          * Math.sin(2 * Math.PI * 1.5 * u - phase);
```

中央付近が滑らかに動き、両端は元の位置につながります。振幅は24pxを開始案とし、
実際の音符・カーソル・下部ステータス欄の描画範囲を測り、安全な上限へ調整します。
振幅の立ち上がりと復帰にはsmoothstep相当の補間を使い、突然曲がったり跳ねたりさせません。
位相は既存のBGM拍・譜面周期に同期します。乱数や描画フレーム数だけでは進めません。
初期位相はπです。通常進行時のカーソルを上側の波へ乗せ、下部ステータス欄への接近を抑えています。
次の譜面の先頭から発動し、会話やコマンド中の停止・復帰でも位相が瞬間移動しないようにします。
発動と復帰の長さは拍単位、効果時間は実際に演奏した2周で管理します。

## 描画する対象

- 棒本体：現在の手描き画像を専用の縦変形フィルターで曲げます。色・太さ・手描きの揺れを保ち、毎フレーム画像を描き直しません。
- 音符：棒と同じ変位を足します。丸いボタンや文字自体は変形・回転させず、読みやすさを保ちます。
- カーソルとコンボ：カーソルの横位置に対応する縦変位を使います。文字は正立させます。
- 長押しの帯：始点だけ動かすのではなく、帯の全長を同じ曲線に沿わせます。帯の親で移動した変位を引き、二重にずれないようにします。
- 押下の光・判定文字・譜面を狙う攻撃の着弾点：同じ座標変換を使い、曲がる前の位置へ残さないようにします。

元の横位置・入力データ・判定時刻は維持します。見た目が曲がったために押す時刻が変わる仕様にはしません。
ネイティブの位置更新後にそのフレームの変位を一度だけ適用し、累積移動を防ぎます。

## 既存実装への接続

対象は敵23・トループ46のモーネ戦だけです。グヌロッベン用のタグ・`_gnuro` 状態を流用しません。

- `KNH_ZXC_Battle_Gnuro.js` の棒フィルター接続・余白・演出後の解除を参照します。
- `KNH_ZXC_Battle.js` の `updateBar()` が音符・カーソルの座標を毎フレーム作るため、その更新順に合わせます。
- 論理座標を参照する長押し、押下アニメ、判定文字、弾の着弾点も調べ、二重変換を避けます。
- 実際の描画先が `bar.bitmap` か `_baseBitmap`／`_meshSprite` か確認し、既存のゆらゆらと共存させます。フィルターは棒の画だけに接続し、音符・文字をまとめて歪めません。
- フィルターの上下余白を確保し、波の山・谷で画像が途切れないようにします。
- 敵の撃破・勝利演出・戦闘中断・シーン終了では、追加フィルターと変位を必ず解除します。次の戦闘には持ち越しません。
- 発動・復帰の命令とウェイトはトループイベント側へ置き、画像処理と会話の進行を分けます。

通常の予約APIは `KNH_CastleUpper.queueMoneWave(24, 2)` です。
HP75％ページでは `KNH_CastleUpper.revealMoneWave(24, 2)` と `this.setWaitMode('moneWaveReveal')` を使い、返答の前に1拍かけて棒を曲げます。
会話中の曲がり始める時間は2周に含めません。次の演奏可能な譜面の頭からBGMの経過を使って実際に演奏した2周を数え、自動復帰します。
会話・コマンド・スキップ中は効果時間と位相を止めます。入力判定のメソッドや横座標は変更していません。
棒と長押し帯にはそれぞれ専用フィルターを掛け、音符・カーソル・判定エフェクトは同じ変位を一度だけ適用します。

## 確認すること

まず振幅0で通常譜面との一致、24pxで棒・短い音符・長押し・カーソルの整合を確認します。
長押しの始点／終点、波の山／谷、画面の両端、通常攻撃と判定エフェクトが重なる場面を見ます。
会話やコマンド、倍速、BGMのループ、勝利・中断からの復帰でも飛びや残像がないことを確認します。
発動中も通常の味方・敵の攻撃を有効にし、入力の成否・コンボ・ダメージが元の判定で動くことを確認します。
最後に別の戦闘とグヌロッベンの棒折りが従来どおり動くことを確認します。
